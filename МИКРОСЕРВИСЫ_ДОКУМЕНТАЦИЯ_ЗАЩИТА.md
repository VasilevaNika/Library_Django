# Связывание микросервисов в Docker: документация для защиты

Три сервиса: **recommendations-service**, **reviews-service**, **notifications-service**.

---

## Одна общая PostgreSQL

Все три приложения подключаются к **одному** контейнеру **`postgres`**, к базе **`library`**, одним логином/паролем (`library` / `library` в `docker-compose.microservices.yml`).

Таблицы в одной БД:

- каталог и списки — миграции **recommendations** (`alembic_version_recommendations`);
- отзывы — **reviews** (`alembic_version_reviews`);
- уведомления — **notifications** (`alembic_version_notifications`).

Три отдельные таблицы версий Alembic, чтобы цепочки миграций не пересекались.

**Порядок запуска** (и миграций): `recommendations-service` → `reviews-service` → `notifications-service` (`depends_on` в Compose).

---

## Логика отзыва

Проверка пользователя и книги — по общей БД. После опубликованного отзыва с `book_id` книга может попасть в `reading_list_entries`; уведомление — HTTP `POST` на сервис уведомлений.

---

## Запуск

```bash
cd Library_Django
docker compose -f docker-compose.microservices.yml up --build
```

Порты: **8001** / **8002** / **8003** для API, **5434** — Postgres на хосте.

При переходе со старых двух контейнеров Postgres выполни сброс томов и подними заново (данные из старых томов в новую схему не переносятся автоматически):

```bash
docker compose -f docker-compose.microservices.yml down -v
docker compose -f docker-compose.microservices.yml up --build
```

Сиды пользователей/книг снова накатятся из миграций recommendations.
