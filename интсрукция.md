# Инструкция по деплою проекта на сервер
## Введение
Сервер уже настроен. На нём установлен Gitea (аналог GitHub). Ваша задача — задеплоить свой микросервис так, чтобы он стал доступен по адресу https://team30.klsh.ru (пример). Деплой будет происходить через Gitea Actions (аналог GitHub Actions).

## Шаг 1. Вход в аккаунт Gitea
Что нужно сделать: Зайти на сайт Gitea (адрес даст преподаватель) под общими учётными данными.
Логин: team30
Пароль: team30pass
Зачем: Чтобы создавать репозитории, настраивать токены и запускать CI/CD.

## Шаг 2. Создать токен для доступа к репозиторию
Что такое токен? Это секретный ключ, который заменяет пароль при работе с Git (push, pull). Он безопаснее, чем пароль.
Что нужно сделать:
В Gitea перейдите в Настройки → Приложения
Нажмите Создать новый токен
Укажите название, например my-token
Поставьте галочки на все доступы (чтение и запись для репозиториев)
Нажмите Создать
Скопируйте токен (он показывается только один раз!)
Где использовать этот токен:
При git push вместо пароля вводите этот токен
Или сохраните в файл ~/.gitconfig (инструкция в readme)
Зачем: Без токена вы не сможете отправлять код в репозиторий и запускать CI/CD.

## Шаг 3. Настроить локальный Git (чтобы не вводить токен каждый раз)
Что нужно сделать: Отредактировать файл ~/.gitconfig на своём компьютере. Добавить туда:
```
gitconfig
[credential]
    helper = store

[url "https://teamN:YOUR_PRIVET_TOKEN@git.klsh.ru/"]
	insteadOf = https://git.klsh.ru/

[url "https://teamN:YOUR_PRIVATE_TOKEN@git.klsh.ru/"]
	insteadOf = git@git.klsh.ru:
```
Затем выполнить один раз git push, ввести логин team30 и токен (вместо пароля). Git запомнит их.
Зачем: Чтобы при каждом git push не вводить логин и токен заново.

## Шаг 4. Создать токен для CI/CD (Gitea Actions)
Что такое RUNNER_TOKEN? Это специальный токен, который позволяет Gitea Actions запускать пайплайны на сервере.
Что нужно сделать:
В Gitea в том же разделе Приложения создайте второй токен
Назовите его runner-token
Поставьте галочку package (чтение и запись)
Скопируйте токен
Перейдите в Settings вашего репозитория → Actions → Secrets → New secret
Имя секрета: RUNNER_TOKEN
Значение: вставьте скопированный токен
Зачем: CI/CD pipeline (автоматическая сборка и деплой) использует этот токен, чтобы получить доступ к вашему репозиторию и образам.

## Шаг 5. Подготовить файлы для деплоя
В вашем репозитории должны быть следующие файлы.
5.1. Файл docker-compose.prod.yml
Что это: Описывает, как запустить ваш микросервис на сервере. Он не собирает образы, а использует уже готовые из реестра.
``` yaml
version: '3.8'

services:
  app:
    image: git.klsh.ru/team30/название-репозитория:latest
    ports:
      - "8000:8000"
    environment:
      - DATABASE_URL=postgresql://...
```
Зачем: Чтобы на сервере знали, какой образ запускать и с какими настройками.
5.2. Три workflow-файла (в папке .gitea/workflows/)
Эти файлы описывают автоматические процессы. Все три запускаются вручную из интерфейса Gitea.
Файл
Что делает
ci-cd.yml
Запускает тесты, собирает Docker-образ, пушит его в реестр Git.klsh.ru
deploy-check.yml
Скачивает образ, поднимает контейнер (docker-compose up), проверяет, что сервис отвечает
teardown.yml
Останавливает и удаляет контейнер (освобождает ресурсы сервера)

Зачем: Чтобы весь процесс был автоматизирован и воспроизводим.

## Шаг 6. Запустить деплой
6.1. Закоммитить и запушить код
``` bash
git add .
git commit -m "Подготовка к деплою"
git push origin main
```
Важно: Сам по себе git push не запускает деплой. Только загружает код.
6.2. Зайти в Gitea Actions и запустить пайплайн
Откройте репозиторий в Gitea
Перейдите в раздел Actions
Выберите CI/CD Pipeline → нажмите Run workflow
Дождитесь зелёных галочек (все шаги успешны)
6.3. Запустить деплой на сервер
В том же разделе Actions выберите Deploy Check → Run workflow
Дождитесь сообщения «Django responded» (или «FastAPI responded»)
6.4. Проверить результат
Откройте в браузере: https://team30.klsh.ru
Если видите свой сервис — деплой успешен.

## Шаг 7. Остановить сервис (после демонстрации)
Зачем: Чтобы не занимать ресурсы сервера.
В Actions выберите Teardown → Run workflow
Контейнер будет остановлен и удалён.
